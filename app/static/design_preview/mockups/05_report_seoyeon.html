💪 강점

RAG 파이프라인의 청킹·임베딩·하이브리드 서치·환각 가드까지 전 구간을 직접 설계하고, 모든 의사결정을 Recall·지연 같은 수치로 뒷받침한다. 특히 인용 강제의 허점을 스스로 발견해 NLI로 보완하고, 응답 지연 장애의 병목을 검색 단계로 정확히 좁혀 해결한 점에서 신입을 상회하는 실전 감각과 깊이가 드러난다.

🌱 보완점

평가셋 50개, 인턴 6개월 규모에서 검증된 경험이라 대규모 트래픽·대용량 데이터 파이프라인에서의 안정성은 추가 확인이 필요하다. 완성도에 욕심이 많아 일정 관리가 흔들린 이력이 있으나 본인이 시간 박스로 관리 중이며, 질문 유형별 검색 분기 등 미완 과제를 다음 단계로 명확히 인지하고 있어 성장 여지가 크다.

💬 면접 Q&A 요약
8문항 · 핵심 발췌
Q1RAG 파이프라인 전체 아키텍처를 단계별로 설명기술심화
수집(3종 소스)→Unstructured 파싱→의미단위 청킹(768/128, 조항 헤더 prefix)→임베딩 bge-m3 교체(Recall 0.71→0.83)→Qdrant 하이브리드(dense+BM25)→reranker. 단계마다 교체 근거를 수치로 제시.
Q2dense·sparse 점수 결합 방식과 정규화기술심화
min-max 가중합의 분포 불안정을 RRF(k=40)로 전환해 안정화. 검증셋 50개 A/B로 dense:sparse 6:4 도출, 질문유형 분기는 다음 과제로 인지.
Q3환각(hallucination) 대응기술심화
인용 강제 + 검색점수 임계 가드 + 사후 NLI 검증 3중. 인용 번호만 맞고 내용 불일치하는 함정을 직접 짚고 문장단위 인용으로 교정. 신고 절반 이하로 감소.
Q5운영 중 성능 장애 원인 추적경험기반
응답 8초 지연을 로그로 검색 단계 병목으로 특정. HNSW ef_search를 Recall-지연 동시 측정으로 튜닝, 오래된 문서 컬렉션 분리 → 3초 이하 복구 + 단계별 모니터링 신설.
Q6기술 의견 충돌 해결인성
멘토의 dense 단독 주장에 대해 실패질문 20개로 Recall 0.62 vs 0.81 비교실험을 만들어 설득. "가설이 틀렸다면 깔끔히 수용" 태도.

이서연 지원자는 RAG/LLM 백엔드의 전 구간을 직접 경험했을 뿐 아니라, 각 선택을 정량 지표와 트레이드오프로 설명할 수 있는 드문 신입 후보다. 환각 제어·하이브리드 서치·검색 장애 대응에서 가설-검증-재발방지로 이어지는 사고 루프가 일관됐고, 멘토와의 충돌도 데이터로 풀어내는 성숙함을 보였다. 대규모 운영 경험은 부족하나 학습 속도와 자기객관화를 고려하면 빠르게 메울 격차로 판단되어 추천한다.
